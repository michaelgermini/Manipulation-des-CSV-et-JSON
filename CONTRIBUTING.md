# Contributing to CSV & JSON Professional Guide

First off, thank you for considering contributing to this project! 🙏

## How Can I Contribute?

### Reporting Bugs
If you find a bug, please create an issue with:
- Clear title describing the bug
- Detailed description
- Steps to reproduce
- Expected vs. actual behavior
- Example code if applicable

### Suggesting Enhancements
Enhancement suggestions are welcome! Please include:
- Clear title
- Detailed description
- Use case / motivation
- Possible implementation approach (optional)

### Adding Content
We welcome:
- **New chapters** on topics not yet covered
- **Code examples** in additional languages
- **Case studies** from your experience
- **Translations** to other languages
- **Corrections** to existing content

### Fixing Documentation
Typos, grammar errors, and clarity improvements are always welcome!

## Contribution Process

1. **Fork** the repository
   ```bash
   git clone https://github.com/YOUR_USERNAME/Manipulation-des-CSV-et-JSON.git
   cd Manipulation-des-CSV-et-JSON
   ```

2. **Create a branch** for your changes
   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/issue-description
   ```

3. **Make your changes**
   - Keep commits atomic and descriptive
   - Follow the existing markdown format
   - Add code examples where relevant
   - Test code examples if applicable

4. **Commit with clear messages**
   ```bash
   git commit -m "Add [chapter/section]: Description of changes"
   ```

5. **Push to your fork**
   ```bash
   git push origin feature/your-feature-name
   ```

6. **Create a Pull Request**
   - Title: Clear description of changes
   - Description: Explain what and why
   - Link any related issues

## Style Guidelines

### Markdown
- Use proper markdown syntax
- Use consistent heading levels
- Include code blocks with language specification
- Add tables for comparisons
- Use proper emoji for visual clarity

### Code Examples
- All code should be production-ready
- Include error handling
- Add comments explaining complex logic
- Test code before submitting
- Include usage examples

### Chapters
- Begin with clear objectives
- Include table of contents for long chapters
- Provide practical examples
- End with exercises
- Reference related chapters

## Commit Message Guidelines

```
[Type] Subject - max 50 chars

Body - explain what and why (not how)
- Use bullet points if needed
- Reference issues with #123

Example:
[docs] Add Chapter 31: Real-time Dashboard Example

- Complete worked example of building real-time dashboard
- Covers Kafka streaming, Spark Structured Streaming
- Includes Docker Compose setup
- Addresses issue #45
```

**Types**: docs, feat, fix, chore, style

## Code of Conduct

- Be respectful and inclusive
- Welcome different perspectives
- Focus on the work, not the person
- Help others learn and grow
- Report harassment or exclusion
